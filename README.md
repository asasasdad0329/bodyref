# BodyRef 實尺人台

**[直接開啟 BodyRef（GitHub Pages）](https://asasasdad0329.github.io/bodyref/)**

輸入身高、體重、三圍和各部位量測，即時生成依真實尺寸換算的 3D 人台。以 AI 生圖與角色設計的體型參照為主，允許美型、誇張比例與後續修型；尺寸精確和曲線、部位連接的品質都要顧到。

這個專案有兩個目的：

1. **讓數據有實體**：大部分 3D 軟體的體型調整用的是抽象滑桿（「胸部 +20%」），不是公分。這裡在模型上量到的每一圈，都等於你輸入的數值。
2. **讓描述可以對齊**：「160 公分、50 公斤、C 罩杯」到底長什麼樣子？與其各自想像，不如直接生成一個人台，截圖或分享代碼給對方看。適合當作 AI 產圖、角色設計、服裝打版時的體型參照。

## 功能

- **填你知道的就好**：每個數值不是「手動」（你填的），就是「推算」（依你填的數值與體型算出）。推算值旁邊列出一般人的常見範圍（約 10%–90%）。
- **體重跟著體型走**：預設不鎖體重。把腰圍改粗，脂肪會長在腹部、腰側、下背，體重和體脂率跟著變重；手動鎖定體重時，多用或省下的組織重量會在其他部位補償；只有一起鎖定體脂率才固定脂肪總量。
- **同樣 BMI 可以長得不一樣**：體脂率與骨骼肌率可各自鎖定。固定胸腰臀時也會重新分配組成，呈現脂肪覆蓋與肌腹的差異；脂肪、骨骼肌、其他去脂量分開記帳。
- **罩杯只管胸部**：罩杯指定上下胸圍差；底座、飽滿位置、中央分離與垂墜由胸部基礎形變處理，體脂改變時仍重新校正胸圍及體積。罩杯選單到 S（上下胸圍差 55 cm）。
- **比例**：腿長比（股下 ÷ 身高）、大腿：小腿、手臂長比、上臂：前臂。比例和四肢長度互斥：改比例時長度依比例推算，改長度時比例由長度算出。
- **現實檢核**：你填的每個數值，都會和「同性別、同身高、其他已填數值也相同」的人比較，列出它大概落在第幾百分位；模型做不到的組合（例如超出模型範圍的罩杯）也會列出。
- **3D 檢視**：白模人台（無五官的蛋形頭、有手指腳趾）；凹處（肚臍、腋下）稍微壓暗；以模型為中心旋轉、平移、縮放；正面／斜側／側面／背面一鍵回正；畫面上方的工具列切換結構線／網格／無、輪廓線、量測線與手臂角度。
- **輸出**：目前視角截圖、正交三視圖（同比例尺，附量測表）、分享連結與分享代碼。

## 怎麼做到的

### 1. 數值連動（`src/core/linkage.ts`）

把身高、體重、體脂與量測共 18 項數據（身高、體重、體脂率、10 個圍度、肩寬、4 個長度）視為一個多變量常態分佈，長度與重量取對數。你鎖定的數值當作已知條件，其餘項目取條件期望值，條件變異數換算成常見範圍；少見程度也是同一套計算。

- **連動關係**（共變異數）來自 [ANSUR II](https://www.openlab.psu.edu/ansur2/)：2012 年美國陸軍人體計測，1,986 名女性、4,082 名男性，公有領域。
- **平均值**來自 `src/core/reference.ts` 的台灣／東亞年輕成人參考體型。
- ANSUR II 沒有量的項目用模型補上：體脂率由 BMI（Deurenberg 公式）加上腰、臀、二頭肌圍的偏差估算；下胸圍由胸圍減去上下胸圍差，胸圍差大多是個人差異、只有一小部分和體脂相關。細節寫在 `tools/prepare_stats.py`。
- 骨骼肌率獨立於這套統計；沒有對應的 ANSUR 共變異數，也不參與罕見程度排名。
- 比例（`src/core/proportions.ts`）先換算成四肢長度，再交給連動模型。

### 2. 人體網格（`src/body/mh/`）

人體網格與形變目標來自 [MakeHuman](https://github.com/makehumancommunity/makehuman)（CC0）。網格是一整塊封閉的身體（約 13,000 個頂點），所以關節處沒有接縫。

形狀分三層，像捏黏土：先有骨架，再貼上「有重量的肉」（`rings.ts`）。

1. **骨架與截面圈**：身高（整體縮放）、四肢長度（MakeHuman 的長度形變）、肩寬，以及頸、手腕、腳踝、下胸圍。軀幹、手臂、腿各有一串水平的「圈」，每一圈分成外側、內側、前、後四個方向各自縮放，圈和圈之間用單調三次曲線（PCHIP）接起來，所以腰、臀、大腿之間是順的，不會折出 V 字。
2. **有重量的部位**：脂肪分成全身一層與胸、下腹、腰側、下背、上背、臀、臀側、大腿、小腿、上臂、頸等分區，骨骼肌分成軀幹、胸大肌、臀肌、大腿、小腿、手臂，其他去脂量使用獨立廣域支撐場。量體以圓頂為基礎（會稍微下垂、往邊緣變薄），臀後與臀側的承托範圍隨目標臀圍／身高平滑展寬，臀側接至大腿上外側；腰腹與下背使用重疊的支撐範圍。脂肪覆蓋、肌腹方向與負重也參與形態。四肢則在那一段的圈各方向放大（小腿的肉在肚子，不是整條均勻變粗）。每一區「一單位」有多重，是用網格體積 × 脂肪或肌肉的密度算出來的；臀部範圍改變時，重量與尺寸響應也重新校準。
3. **胸部**：女性以 MakeHuman 胸型為底稿，搭配橢圓底座、偏下飽滿位置、中央淡出與垂墜，根部避免跨入下胸圍。男性胸大肌採胸骨至肩側的扇形，脂肪則是向腋側延伸的覆蓋層；兩者不共用乳房圓頂。胸型選單留待後續模組，基礎介面已拆出。

**總量分配**（`fitComposition`）：

- 體重 × 體脂率 = 脂肪總量；骨骼肌可獨立指定，未指定時以去脂量的 55% 作起點；其餘是其他去脂組織。扣掉素體已有的，照性別的預設比例分到各區（女性偏臀、臀側、大腿；男性偏腹部、腰側）。這組比例是一般印象，不是醫學資料。
- 手動填的圍度（腰、臀、大腿、小腿、上臂，男性的上胸圍）是硬條件：優先調自己負責的區域，直到量起來剛好。廣域增重場在已固定圍度附近平順減弱，避免自由重量一直擠進固定部位。要比素體還細時，脂肪先歸零，再把那一圈本身收小（但有下限，不會壓扁內臟和肌肉該有的空間）。
- 鎖定體重時由自由區補償重量；未固定體脂時差額可由脂肪與去脂量共同承擔。同時指定體脂、肌肉時分別守住總量；固定圍度的部位仍參與肌肉預算重分配，再重新量測對準圍度。
- 未填圍度以連動建議作軟偏好，依條件變異縮放偏差。只在自由區提出小量公斤轉移，脂肪和去脂組織各自守恆；每個候選重新校正手動尺寸、體重與體脂後才評估，沒有改善就縮步或保留有效解。這也限制鎖體重、縮手臂時把剩餘量全塞回臀腿。
- 統計來源的屈臂二頭肌圍、肚臍腰圍與網格的放鬆上臂、最細腰圍定義不同，目前降低相應偏好權重。肩寬仍沿用明示的服裝量法；沒有成對校準資料前不捏造換算係數。
- 體重一律由網格體積算出，所以胸部、骨架的改變也會反映在體重上。

手動條件繼續用割線法逐項對準，局部參數只負責自己的目標；分配偏好另用有阻尼的小步轉移，不把整個造型交給全域求解器。每次從確定的分配起點求解，骨架快取採固定半公分長度格點，最後對準實際長度，避免操作順序改變結果。骨架與形態重量校準分開快取；只旋轉手臂時重用中立姿勢的解。分配校準增加重算時間，可用下方回歸入口量測實際耗時。

量尺寸（`measure.ts`）：圍度是用平面切出截面後的凸包周長，就像拉緊的皮尺；下胸圍與腰圍會跨過胸部下方。位置由關節與標記點決定，「最細處」「最粗處」在一段範圍內搜尋。

人台外觀：拿掉原本的頭，換成依頭部大小生成的蛋形頭（`egghead.ts`）；骨盆附近先抹平 MakeHuman 原本的胯下折線；顯示前用 Taubin 平滑去掉細小凹凸，再依凹陷深度把凹處壓暗；手臂以骨架權重轉到指定角度（`model.ts`）。

這些都在 Web Worker 裡執行（`src/body/worker.ts`），拖動滑桿時畫面不會卡住。

## 準確度與限制

- 手動填的圍度與長度精確：測試涵蓋誇張沙漏、偏胖、高壯男性、G 與 S 罩杯、細腰但體重重、臀圍序列與手動上臂，網格上量到的數值和目標相差在 0.5 cm 內，鎖定的體重在 0.5 kg 內、體脂率與骨骼肌率在 1 個百分點內；另檢查相鄰輸入的連續性及操作順序的一致性。
- 只填身高時，參考體型的體重與體脂接近參考值（測試檢查 4% 與 3 個百分點內）。
- 罩杯做到約 S（上下胸圍差 55 cm）；更大罩杯尚未列入支援，需要後續胸型模組與驗收。做不到的組合會在現實檢核列出。
- 解剖參照如何轉成表面規則見 [設計說明](docs/ANATOMY_SHAPES.md)。初始脂肪分佈仍是造型預設，之後由未填圍度的統計偏好校準；不是醫學上的分段體組成估計，也不保證所有未填圍度落在建議值 ±2～3 cm。手動的極端比例仍可保留。
- 極端大臀的未填大腿仍可能比統計建議粗；命名胸型、腹肌細紋及個人的脂肪分布尚未提供。
- 建議值是「統計上的典型」，不是唯一答案；ANSUR II 是美國軍人，連動關係套用到一般人時會有偏差。
- 量測位置與量法說明寫在每個欄位下方。上臂圍量在上臂中段；腰圍是肋骨與骨盆之間最細處；肩寬是左肩點經過後頸點到右肩點（服裝量法）。

## 開發

```bash
npm ci
npm run dev      # 開發伺服器
npm test         # 連動模型與網格的測試
npm run test:body-report -- /absolute/output/body-report.json  # 產物必須在倉庫外
node tools/body-visual.mjs /absolute/output/body-views  # 系統 Chrome；四視圖與 UI 條件檢查
npm run build    # 輸出到 dist/
npm run build:single   # 另外打包成單一 HTML（dist/bodyref-single.html），不需要伺服器就能打開
```

協作規則（含 AI 編碼代理）寫在 `AGENTS.md`；目前狀態、已知問題與還沒做的規劃在 `docs/HANDOFF.md`，開發過程與每次轉向的理由在 `docs/HISTORY.md`。

開發與 CI 使用 Node.js 22（22.12 以上）。CI 另保存代表案例的 `body-visual` 圖片附件（正面、側面、背面、斜後）；四視圖工具加上 `all` 可跑全部自身案例。數值與四視圖工具都只寫入指定的倉庫外目錄，不把產物放入 Git。

### 重新產生資料檔

`public/body.bin`、`src/body/mh/manifest.json` 與 `src/core/statsModel.json` 都由 `tools/` 裡的腳本產生，需要 Python 3 與 numpy：

```bash
git clone --depth 1 https://github.com/makehumancommunity/makehuman /tmp/makehuman
python3 tools/prepare_body.py /tmp/makehuman/makehuman/data

# ANSUR II 的 CSV 可從 https://www.openlab.psu.edu/ansur2/ 下載
python3 tools/prepare_stats.py "ANSUR II FEMALE Public.csv" "ANSUR II MALE Public.csv"
```

## 架構

```
src/
  core/                 與 3D 無關的數據層
    measurements.ts     量測項目的定義（名稱、量法、範圍），介面依這份清單產生
    reference.ts        參考體型、罩杯表、人體密度公式
    linkage.ts          數值連動：建議值、常見範圍、少見程度
    proportions.ts      身體比例與四肢長度的換算
    statsModel.json     由 ANSUR II 算出的共變異數（tools/prepare_stats.py 產生）
    analysis.ts         摘要數據與現實檢核
    state.ts            狀態、範例體型、瀏覽器儲存、分享代碼
  body/
    client.ts           主畫面與背景執行緒之間的橋梁
    goals.ts            把面板狀態換成網格求解的硬條件與未填圍度的軟偏好
    worker.ts           背景執行緒
    mh/                 MakeHuman 網格的處理
      asset.ts          讀取資料檔、套用形變目標
      geometry.ts       切截面、凸包、體積、平滑
      measure.ts        在網格上量尺寸
      rings.ts          骨架與截面圈、脂肪與肌肉的部位、總量分配與求解
      distribution.ts   自由組織的受限公斤轉移與軟偏好評分
      model.ts          顯示前的平滑與擺手臂
      egghead.ts        人台頭與脖子
      guides.ts         結構線
      engine.ts         把以上組成畫面需要的輸出
  view/                 Three.js 顯示層
  ui/                   面板、摘要、匯出與分享
tools/                  資料準備、數值回歸與單檔打包腳本
```

### 常見的擴充方式

- **新增量測項目**：在 `core/measurements.ts` 加一筆定義、在 `tools/prepare_stats.py` 對應到 ANSUR II 的欄位、在 `body/mh/measure.ts` 定義怎麼在網格上量、在 `body/mh/rings.ts` 決定由哪一圈或哪一區負責，並在 `body/goals.ts` 決定它是骨架（照建議值）還是軟組織（只有手動填才固定）。
- **脂肪分佈**：`rings.ts` 的 `FAT_SHARE`（變胖）、`LOSS_SHARE`（變瘦）、`LEAN_SHARE`（去脂組織）決定初始分配，再依未填圍度的軟偏好校準。新增 InBody 分段輸入時，需一起處理初始分配與總量條件。
- **型態指定（胸型、臀型）**：每一塊肉的位置、範圍、下垂與變薄方式都寫在 `rings.ts` 的 `build`；胸型、臀型可以做成這些數值的預設組合（例如水滴、圓盤、碗公）。修改形狀後須同步校準體積與尺寸響應，維持手動尺寸與總量條件。
- **姿勢**：MakeHuman 的骨架與蒙皮權重（CC0）可以直接用；目前只用來轉手臂角度。
