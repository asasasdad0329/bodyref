## 開啟及重現

```bash
npm ci
npm run dev
# 開啟 http://localhost:5173/shape-lab.html
npm run build:shape-lab
# 另以 HTTP 伺服器提供 dist-shape-lab，開啟 shape-lab.html
npm run test:shape-report -- /tmp/bodyref-shape-report.json
```

正式網站與原型各自建置，避免把未驗收的控制混入人體求解、分享代碼與離線單檔。CI 的 `shape-control-previews` 附件保存四張固定視角截圖，`shape-control-lab` 附件保存可用 HTTP 伺服器開啟的獨立驗收頁；圖片不 commit。生成截圖成功只證明工具能重現，不代表外型已合格。

驗收頁上排是固定基準，下排是當前形變；正、前斜、側、後斜、背視角共用正交比例尺。抬手 60° 露出腰臀，關閉量測／結構疊線，另可開啟局部座標與權重。下載對照圖會保留視角與尺寸標籤。控制表及 JSON 輸出列出父參照、局部軸、支撐柄、方向、範圍與每個頂點的權重。

## 控制與權重

`src/body/mh/shapeControls.ts` 建立 18 個控制自由度：腹前、下腹，左右腰側、後腰、臀上、臀後、臀側、下臀、大腿根外側及後側。胸廓下緣、骨盆、骶骨提供父參照；局部軸是外側、上、前，右側的外側軸反向。每個控制有一個方向振幅，附帶少量聯動的上／下移。參數是公分振幅，不是公斤。範圍在 160 cm 基準為 −1～8 cm，隨身高縮放；它是原型探索範圍，不是生理界限。

先用 torso／thigh 的拓撲和上下支撐帶決定可動區，再從各控制柄沿實際網格邊傳播測地距離，固定零邊界，迭代求解帶控制柄的 screened Laplacian 平滑權重。這避免只憑空間球形距離跨過臀溝或左右腿。後中線與會陰附著使用漸變限制。鄰接控制最後共用歸一化權重，任一頂點的權重總和不超過 1；各區不重複加上整份控制位移。

這是表面控制籠的第一個版本，尚非完整多軸骨變換或完成校準的解剖模型。控制架構可保留基準上的已有修型；此輪沒有另外雕刻新的基準。中性位移逐頂點等於舊基準，關節輔助點不受局部增脂／增肌影響。新骨架建立後會重新取得局部參照及權重；姿勢蒙皮仍由原 `BodyModel` 負責。

## 尺寸、體積與聯動

臀肌模式偏臀上／臀後，脂肪覆蓋模式偏臀側／下臀及腿根。係數是可檢查、待校準的造型設定，沒有宣稱來自文獻的通用增長比例。兩者均由同一套局部控制產生，不另疊任意圓頂。

求解臀圍只沿非負模式振幅二分搜尋，並重新切實際網格量測，不以預估周長替代。限制大腿時，先把聯動增量從腿根／下臀移向臀上／臀後，再在同一模式中搜尋能同時滿足臀圍及基準大腿誤差 < 0.5 cm 的結果。這個原型尚不能任意指定新的大腿／腰圍；「固定大腿」指限制相對本次基準的量測差，不是把所有腿根頂點鎖住。沒有負向削洞補償。

報告逐一記錄單控制的 −0.5／+1 cm 響應、體積、量測截面，以及兩種模式的臀圍 +0／2／5／10／20 cm 序列與固定大腿結果。未達標照實記錄殘差。

目前三個基準在 +2 cm 臀圍、固定大腿時，兩種模式均能達到臀圍與大腿誤差 < 0.5 cm；參考體型大腿差約 0.39／0.49 cm。參考體型固定大腿增臀 +5 cm 時，臀肌／脂肪模式仍分別短約 2.43／2.98 cm，需改善模式，不能當作使用者的體型不相容。較大幅度尚未完成外型校準。

實際網格體積獨立量測，尚不換算新增肌肉或脂肪公斤。尚未接入獨立肌肉記帳、全身補償或 InBody。相同臀圍的模式對照只能證明局部分布不同，不能稱為已完成同尺寸的全身組成預測。

## 基準與驗證界線

`tests/fixtures/shapeBaseline.json` 固定 `f4e2aff` 應用程式算法的三個基準（目前 main 的應用程式即此版），保存資產 SHA-256、量測、體積、腰臀腿截面及鏡頭定義。這份基準不能在造型退步時隨新結果一起更新。報告與大份權重產物放倉庫外。

`tests/body.test.ts` 包含中性重現、輸入順序、基準數字／截面、支撐外不動、權重非負及分割、單側局部性、同臀圍模式差異、固定大腿側寬、無負向抵消、序列單調、相鄰權重斜率及參考體型聯動的面方向檢查。這些只防數值與基本幾何故障，不證明沒有所有自交或外型已自然。

下一個檢查點是作者檢視控制熱圖和五視角原型，定位後腰／臀側／臀下連接仍需的修型，改善固定大腿時的較大增量。外型合格後再校準公斤響應及接回受限尺寸求解。比例介面、獨立肌肉記帳和後兩步維持未完成狀態；不可把這個原型當成整份計畫已交付。
