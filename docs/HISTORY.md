# 開發歷程

這份文件補充 Git 紀錄讀不出來的部分：每個階段為什麼這樣做、遇到什麼問題、為什麼換掉。commit 雜湊可以用 `git show <雜湊>` 對照。

## 1. MVP 與外觀（2026-10-17）

- `a70f46f` 建立網站骨架：面板輸入、3D 預覽、摘要。
- `5279b84` 人台改成白模外觀（無五官、結構線），因為用途是體型參考，不需要寫實的臉。
- 定下的方向：輸入可以很少，沒填的由統計連動補上；抽象人台加線條；可自由旋轉、截圖、三視圖；固定姿勢。

## 2. 真實網格與數值連動（2026-10-17）

- `796b581` 改用 MakeHuman 的人體網格（CC0），並用 ANSUR II 的共變異數做數值連動（`src/core/linkage.ts`）：鎖定的數值當已知條件，其餘取條件期望值。平均值換成台灣／東亞年輕成人。
- 理由：程序生成的身體再怎麼調都不像人；MakeHuman 有成熟的拓撲與大量形變目標。

## 3. 身體組成求解器（2026-10-17 ~ 18）

- `fd4b9fc` 把求解器改成「瘦的基礎身體 + 三段肌肉 + 13 個脂肪堆積區」，用加權高斯-牛頓法同時對準所有目標。
- `1de6c9f` 顯示前平滑表面、凹處壓暗（肚臍才看得出來）。
- `c790f90`、`c64b3dd`、`37ae72f` 比例（腿長比等）、畫面工具列、面板分層、比例群組預設收合。
- `084bdcb`、`2449e60` 極端輸入時求解器發散（曾經自動跑到三百多公斤、模型消失）：改成「目標函數變好才接受這一步」，再改用 Levenberg–Marquardt 阻尼。

**這一版的根本問題**（試用後發現）：

- 腰、臀、大腿交界折出一個 V 字。追查後發現是 MakeHuman 的量測形變目標彼此疊加造成的，和網格本身的胯下結構也有關。
- 全域求解會拿任何參數去湊任何目標，結果是：體重增加時上臂反而變細、肩寬像被鎖住、小腿均勻變粗（小腿肚和腳踝應該不同）。
- 「先決定數字，再生形狀」的思路下，形狀是副產品，很難控制。

## 4. 截面圈原型（2026-10-18，分支 `proto/rings`）

討論後的新方向：**形狀骨（截面圈）+ 有重量的體雕部位 + 總量分配**。參考了遊戲捏人系統的公開作法（大量形狀骨、平滑蒙皮，所以拉到極端也不破圖），但沒有使用任何遊戲資產。

- `c8ab8a3` 軀幹改成一串水平截面圈，圈之間用單調三次曲線（PCHIP）接起來。單調是關鍵：普通樣條會在圈之間過衝，產生新的凹凸。
- `7c402ae` 每一圈分成外側、內側、前、後四個方向各自縮放。只有一個縮放值時，下腹和腹股溝會不自然地凹陷。
- `b682bfb` 臀部、臀側、下腹改成「有位置的圓頂狀肉塊」。只靠截面圈時臀部變成三角錐。骨盆附近先用 Taubin 平滑抹掉 MakeHuman 原本的胯下折線（V 字的來源）。
- `c297bd1` 推廣到全身：手臂、腿、頸也是一串圈；手腳跟著移動，小腿不平滑（否則會變成柱子）。
- `1f6fd0d` 加入真實的 170 cm／97 kg 男性案例當驗收。
- `2a6bf76` 比較新舊模型的腰部截面。
- `1191366` 用身體組成驅動：每一區有公斤數，「一單位」的重量由網格體積 × 密度校準；鎖定的圍度只調自己負責的區，要更細時才收那一圈；鎖體重時總脂肪量守恆。

過程中的形狀問題與修法：男性胸前出現一片平板 → 改成以乳頭為中心的圓頂；背部折痕 → 上下背的肉塊重疊；胸部縮不小 → 允許負值；男性腰下出現裙擺狀凸緣 → 求解時固定量測位置。

## 5. 換上網站（2026-10-19）

- `343e291` 合併原型分支。
- `9766c6c` 網站改用新模型，並處理整合時發現的問題：
  - 拖動滑桿太慢：連動建議的四肢長度會隨腰圍、體重微微變動，每次都重建骨架。改成借用最接近的一份骨架與校準。
  - 沿用上一次的解當起點時，帶到了不該帶的修正量（上一次鎖體重、這次沒鎖），導致同樣的輸入結果不同。加了測試專門檢查。
  - 面板沒有更新成網格量到的數值（判斷「是不是同一次請求」時比的是物件而不是內容）。
  - 罩杯選單延伸到 S；刪除舊求解器。

## 6. 分配偏好與臀部承托（2026-10-20）

- 原來只把統計當起點，手動圍度雖然精確，未填部位在鎖體重、極端腰臀時卻越走越偏。單獨降低手臂固定比例不能同時解決「太粗」與「太細」，因此保留原來的局部硬條件，另對自由組織加入依統計變異縮放的軟偏好。
- 每個候選只在同類組織之間轉移公斤，重新校正手動尺寸與總量後再接受。腰、上臂的來源量法不同，先降低權重；沒有資料支持的量法換算不實作。罩杯不能成為全身分配偏好的輸入。
- 精細分配放大了原本「先遇到誰就借用誰的骨架」的快取差異，改成確定的長度格點與確定的求解起點；一次形變的長度補正不可寫回共用快取。增加了新引擎與已有相近快取的直接比較。
- 大臀不能只抬高固定圓頂。承托範圍依目標臀圍／身高展寬、向上下延伸；衰減逐漸分成上下與環向，保留臀下轉折，同步重算兩個臀區的公斤及尺寸響應。範圍在單次求解內固定，避免每步振幅改變時校準失效。
- 固定視角抓到只看數字會漏掉的退步：男性把自由重量轉去上背，數值誤差雖小，卻長出新的凸塊。男性上背改為保留預設分配，另加回歸；女性胸圍原本就是硬條件，保留既有的校正自由度。
- 代價是分配重算比原本慢；骨架與臀區校準分開快取，只改手臂角度時略過重新分配。回歸工具分開量冷算、經過另一輸入後的重算、完全相同輸入的快取時間，不能拿快取時間當重算速度。
- 增加自身的分配、重量補償、臀圍序列、相鄰輸入連續性與操作順序回歸。外觀調整和分配各存一個開發檢查點；圖像與生成報告不放入原始碼倉庫。

## 7. 解剖表面形態與獨立組成（2026-10-20）

- 作者確認本輪須完成女性腰腹臀腿、女性胸部基礎、男性胸臀三步。解剖用於設計外表的覆蓋範圍、肌腹方向及附著處淡出，不改成內部肌束／脂肪細胞的即時模擬。來源與推論範圍另列 `docs/ANATOMY_SHAPES.md`。
- 「骨骼肌率」原本只是改體脂的另一種寫法，現在成為獨立保存及分享的參數。總量分成脂肪、骨骼肌與其他去脂組織；固定圍度的區域仍參與肌肉預算投影，之後再重測對準圍度，不能把固定圍度誤當固定肌肉公斤數。
- 只加體重、沒指定體脂時，原來把全部修正量當脂肪。現在脂肪與去脂量共同補償；廣域負重在固定部位附近平順減弱，避免局部圈已收到下限後仍不斷把量塞回去。遇到局部響應停滯時重新探測斜率。
- 臀側承托延伸至大腿上外側，女性腰腹與後腰支撐重疊；臀肌和臀脂分離。驗收包含「大腿圍固定仍增加正面臀側寬度」，不以全條大腿變粗代替銜接。
- 女性胸部有獨立脂肪記帳，尺寸修正與胸脂增量合併後再決定底座足跡，避免兩個場互相抵消時把支撐範圍放大。底座、飽滿位置、中央分離、垂墜抽成介面，命名胸型留後續。男性胸大肌改為扇形足跡，胸脂用胸廓覆蓋層，不沿用乳頭圓頂。
- 四視圖另抓到尺寸通過但大罩杯變成長錐形的退步：正增量改沿曲面向側邊與上下展開，根部遮罩只保護胸廓，乳房下極可自然落在量測平面下方。新增乳房前後深度相對垂直範圍的美術回歸上界，避免再只看胸圍。
- 男性的大胸案例也不能只靠胸前量體消化尺寸差額：改由胸廓圈對準周向尺寸，肌脂場提供扇形肌腹與覆蓋。上方承托延展，避免單一圈長成尖錐；延展仍須在肩點之前回接，保住固定肩寬。新增胸圍變大時的寬度／前凸比例檢查。
- 校正期間抓到兩類重量出口：未量測的胸大肌與上背不能承擔任意自由轉移；胸部根部也不能因增加覆蓋而推高固定下胸圍。這些均加入尺寸、組成及外觀檢查。
- 罩杯原本仍會透過一次高斯觀測改全身建議，造成換罩杯後腰腹與胸廓改變；已移除這條全身觀測，只保留指定胸圍差。小數罩杯差也進形態快取識別，骨架格點則採確定的標準化起點。
- 新增自身案例的固定圍度增重、體脂／肌肉交換、組成總和與不相容殘差測試；CI 使用系統 Chrome 保存代表案例四視圖附件。圖片與原始驗收輸出留在 artifact，不進 Git。

## 8. 胸壁分離與外型退步修正（2026-10-20）

- 作者檢視後指出男女胸部失形、臀下／臀側／後腰銜接仍不合格、後腰中線突出，以及比值介面漏做。上一輪數字與截圖程序通過，不代表外型過關。
- E 罩杯配細腰大臀也出現上胸圍殘差。原因包含胸廓與乳房共用縮放、把乳頭小片區當底座、乳房下極混入胸廓量測，以及離散胸峰頂點換排造成皮尺跳動。增加胸部參數上限不能解決這些耦合。
- 胸壁與乳房分離後，胸廓帶動根部，完整底座曲面負責乳房體積；上下胸及胸壁上圈聯合校正。胸壁量測使乳房可越過下胸皮尺；胸峰用相對胸壁的連續前凸區域定位。局部平滑放進尺寸與體積求解，顯示時不再把胸峰削掉。
- 男性胸圍不能等比例撐大後背；胸下也不能沿用女性乳房蒙皮下界。胸大肌保留前側扇形、脂肪保留覆蓋層，胸廓以寬度及前側共同承擔胸圍。
- 負向窄肌腹會把脊柱兩側挖低；收腰只擠兩側也會留下突出的後中線。改為廣域肌肉覆蓋與連同前後覆蓋收圈。臀側支撐提高，臀後上下界與後腰、大腿根聯繫；改形狀後也要重量測當前臀區的分配響應。
- 所有比例以 `1 : 比值` 輸入，儲存值維持相容。新增預設／一般 E 罩杯與範圍案例、顯示尺寸、脊柱中線、男性胸背及實際比例操作回歸；截圖加入無疊線的前後斜視角。

## 學到的事

- **局部性比精確度難**：要精確達成手動數值不難，難的是「改一個數字只動該動的地方」。新模型讓每個目標只能調自己的參數，從結構上保證局部性。
- **形狀要由結構決定，不是由求解器湊出來**：截面圈、圓頂肉塊的形狀及承托範圍由明確的部位規則決定，求解器只決定「多少」。
- **極端值是常態**：需求本身就包含非常規罩杯、極細腰配大臀等組合，所以每次改動都要拿極端案例驗收，不能只看平均體型。
- **快取和沿用上一次的解很容易造成「同樣的輸入、不同的結果」**，要有測試守著。
